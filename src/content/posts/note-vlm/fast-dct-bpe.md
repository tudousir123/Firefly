> 本系列按时间顺序解读 Physical Intelligence（π 团队）的技术文章。上一期我们讲了 π0：用 Flow Matching 让机器人输出精确的连续动作。今天这篇是 2025 年 1 月发布的 FAST，它问的是一个更基础的问题：**机器人的动作，到底应该怎么表示？**

## 一、问题的起点：350 个浮点数怎么喂给 Transformer

当一个 VLA 模型要控制机器人拿起桌上的杯子，它的输出长什么样？机器人有 7 个关节，每个关节在每个时刻都有一个角度值。以 50Hz 控制频率计算（每秒 50 帧），一个动作块（Action Chunk，即 1 秒的控制信号）= 50 个时间步 × 7 个关节 = **350 个浮点数**。

问题来了：Transformer 通常只能处理离散的 token（像文字一样一个一个的符号），这 350 个连续的小数该怎么喂进去？

最朴素的方法是**分箱（naive binning）**：把每个关节角度归一化到 $[-1,1]$，在区间上均匀切成 256 个格子，每个格子对应一个 token 编号。比如角度 0.80 对应第 230 个格子，输出 token ID 230；0.60 对应 204；0.05 对应 136。就像记录温度：把 -50℃～+50℃ 均匀划分成 256 个档位，每一档都是温度的一个"词"。

256 是词典大小。350 个数字每个都要查一次词典，最终得到长度为 350 的 token 序列。这个方法有两个问题：

1. **序列太长**：Transformer 做自回归预测，attention 的计算量随序列长度增长，350 个 token 是不小的开销。
2. **丢失时序连贯性**（更隐蔽）：分箱对每个维度独立编码。机器人的手臂不会突然跳变，相邻时刻的关节角度一定高度相关、平滑过渡；但分箱给出的是 350 个相互独立的 token——模型必须从这堆离散数字里自己学会"手臂应该如何平滑运动"，负担重，而且非常难。

OpenVLA、RT-2 等模型直接用了简单分箱，在复杂的精细操作任务上就很容易失败。

## 二、两条路线：绕开它，还是修好它

**π0 的路线：完全绕开 tokenizer。** VLM 先输出上下文特征（看到杯子、要伸手去拿），然后从随机噪声出发——噪声可以理解为"每个动作都有可能"的状态；Flow Matching 在 VLM 特征的引导下学习一个向量场，迭代约 10 步，每一步都把噪声往正确动作的方向推一步，最后一次性输出 350 个精确的连续动作。

打个比方：就像陶艺拉坯——陶坯从头到尾都是完整的一整块，陶工的每一轮调整都同时作用于整个器形，让它一步步趋向最终的形状；自回归生成则更像砌墙，必须一块砖一块砖地往上垒。所以 Flow Matching 精度更高，而且 350 个值是**同时生成**的，时序连贯性自然保持。

**FAST 的路线：回到 token 生成这条路，但同时解决"序列太长"和"丢失连贯性"这两个问题。**

## 三、核心洞察：机器人动作是"低频信号"

FAST 的核心思路借鉴了信号压缩领域的经验积累：

| 领域 | 方法 | 核心工具 |
|---|---|---|
| 图像压缩（JPEG） | DCT + 丢弃高频成分 | DCT |
| 音频压缩（MP3） | DCT + 心理声学（丢掉人耳听不见的频率） | DCT |
| 机器人动作（FAST） | DCT + BPE | DCT |

关键洞察：**机器人动作曲线和音频信号有相同的统计特征——都是平滑的、以低频成分为主。**

为什么机器人动作是低频的？取关节 1 在 8 个时间步里的角度变化：0.00、0.11、……、0.80，画出来几乎是一条笔直的斜线——手臂从初始位置平滑地移向目标。高频成分（细微抖动）在这种运动里几乎不存在。

## 四、DCT：把时域信号变成频域信号

DCT（离散余弦变换）是 FAST 的核心工具。公式如下：

$$X_k = \sum_{n=0}^{T-1} x_n \cos\!\left(\frac{\pi k (2n+1)}{2T}\right)$$

- $n$：时间步编号；$x_n$：第 $n$ 步的关节角度；
- $k$：频率编号，$k=0$ 是最低频；$X_k$：第 $k$ 个频率分量的强度。

各分量的物理含义：

- $X_0$ 是直流分量，即信号的平均水平——比如机械臂整体在哪个位置；
- $X_1$ 是最低频，代表整体趋势——手臂是在上升还是下降；
- $X_2$ 对应轻微的弯曲——比如略微的加速或减速；
- $k$ 越大频率越高，对应越细微的抖动。对平滑的机器人动作来说，这些分量几乎为 0。

### 用具体数字算一遍

输入是前面那 8 个值（0.00、0.11、……、0.80），$T=8$：

- **$k=0$**：$\cos 0 = 1$，$X_0$ 就是对所有 $x_n$ 直接求和：$0.00 + 0.11 + \cdots + 0.80 = 3.2$——信号的平均水平。
- **$k=1$**：代入余弦函数逐点计算并求和，得到 $X_1 = -1.48$。负号表示整体信号是上升趋势（与余弦曲线的方向相反）。
- **$k=2$**：算出来约等于 0。$X_3$ 到 $X_7$ 也全部接近 0。

**几乎所有的信息，都被 $X_0$ 和 $X_1$ 两个数字捕获了。**

### 直觉理解：DCT 在问什么

DCT 的本质是在问：**原始信号和特定频率的余弦曲线到底有多像？** $X_k$ 的计算方式，就是把原始信号与频率为 $k$ 的余弦基函数逐点相乘，然后求和。

看 $k=2$ 的例子：它的基函数值是 +1.0、+0.4、-0.4、……、+1.0（忽上忽下的震荡曲线）。把它与前面那条单调上升的斜线逐点相乘：正的部分和负的部分基本相互抵消，最后求和约等于 0。直觉上：一条单调上升的斜线和一个忽上忽下的震荡曲线，相似度很低，乘积的正负号相互抵消，所以 $X_2 \approx 0$。

结论：对平滑的线性运动，能量几乎都集中在 $X_0$（均值）和 $X_1$（趋势）这两项——知道这些，就可以进行压缩了。

### 逆变换：两个数字还原八个数字

逆 DCT 公式：给定频率分量，就可以还原回原始时序信号。如果只保留 $X_0$ 和 $X_1$、把其他分量全部置 0，代入 $T=8$ 的简化还原公式，还原结果与原始信号的误差很小——**只用 2 个数字就还原了 8 个数字**。

实际 FAST 系统中，每个关节大约保留 **5 个频率分量**，误差可以进一步降低，足以支持插网线、拧螺丝这类毫米级精度的操作。

## 五、FAST 五步流程

1. **归一化**：把每个关节的角度独立缩放到 $[-1,1]$；
2. **DCT**：对每个关节的 50 帧数据做一次 DCT，把时域信号变成频域信号；7 个关节 × 50 个频率分量，得到 7×50 的频率矩阵；
3. **量化**：把浮点数转化为整数，方便后续处理；
4. **低频优先展平 + 截断高频**：先读所有关节 $k=0$ 的分量（各关节的均值），再读所有关节 $k=1$（整体趋势），然后 $k=2$、$k=3$…… 后面的数字已经很接近 0，直接截断。约得到 **40 个整数**；
5. **BPE 编码**：把 40 个整数进一步压缩到约 **30 个 token**。

整个过程：**350 个浮点数 → 30～60 个 token，压缩约 10 倍。**

步骤 4 体现的是"低频优先"的逻辑：最重要的信息排在前面，不重要的信息直接丢掉。

## 六、BPE：与 GPT 分词器完全相同的算法

BPE（字节对编码）和 GPT 分词器用的是完全相同的算法，核心思想：**找高频 → 合并 → 重复**。

- 初始状态：每个整数都是独立的 token，序列形如 320、185、94、……；
- 统计整个序列中相邻数字对的出现频率，找到最高频的组合——比如 320 后面跟 185 这个组合出现了 8 万次，就给 (320, 185) 分配一个新符号，把所有出现处都合并掉；
- 不断重复这个过程。常见的运动模式（动作中的"惯用语"）会被合并起来，序列从约 40 个整数压缩到约 30 个 token。

## 七、怎么用：开箱即用的预训练 Tokenizer

Physical Intelligence 发布了预训练的 FAST tokenizer——在约 100 万条真实机器人轨迹上训练出来的 BPE tokenizer，**不需要自己收集数据重新训练，可以直接用**。从 Hugging Face 加载，把 action chunk 传进去，输出 30～60 个整数 token（这些就是训练时要预测的 ground truth）。它覆盖多种机器人类型，能泛化到没见过的机器人构型。

## 八、训练与推理

**训练**：用 teacher forcing，和 GPT 的训练方式完全一致——把视觉 token 和语言 token 拼在一起作为条件输入，让模型预测下一个 action token，用交叉熵损失函数训练。action token 就是预测目标。

**推理**：只给模型视觉和语言条件，让它自回归地一个 token 一个 token 生成，然后用 tokenizer 解码，把生成的 token 还原成关节角度。

完整闭环：**图像 + 语言 → 自回归生成 action token → 解码 → 关节控制信号 → 发给机器人执行。**

## 九、实验结果

**① 精细操作任务**（叠衣服、整理桌面、打包购物袋、插网线）：

| 方法 | 成功率 |
|---|---|
| 简单分箱（OpenVLA、RT-2） | ≈ 0 |
| FAST | ≈ 80% |
| Flow Matching（π0） | ≈ 85% |

FAST 与 Flow Matching 结果相当。这是一个重要里程碑：此前学界普遍认为精细操作只能用 diffusion 或 flow matching 完成，**FAST 证明了自回归 token 同样可以做到**。

**② 训练速度**：达到相同的任务成功率，π0 的 Flow Matching 需要约 10 万步训练，π0-FAST 只需约 2 万步——**快了 5 倍**。三个原因：

1. **序列更短**：30～60 个 token 对比 350 个，计算量明显降低；
2. **训练目标对齐**：自回归 token 与语言模型预训练完全一致，迁移学习更高效、梯度方向更稳定；
3. **语义压缩**：DCT+BPE 把轨迹的形状编码进了 token，模型不再需要从原始数据里学习"运动应该是平滑的"这件事。

**③ 泛化能力**（JOI 数据集）：一个由多机构（UC Berkeley、Stanford、华盛顿的大学、韩国的大学等）共同维护的开源机器人数据集。实验设定：测试地点在训练数据里从未出现过，直接部署，让机器人在完全陌生的环境里执行语言指令。结果：**π0-FAST 在所有测试地点都能成功执行**——在它之前，所有 VLA 方法（包括原版 π0）在陌生环境下的成功率几乎为 0。作者认为原因在于：更短的 token 让模型可以在更大规模、更多样化的数据上训练，泛化能力自然更强。

## 十、短板与对比

FAST 也有短板：**推理速度变慢了**。

π0 的 Flow Matching 是并行的：从噪声出发迭代 10 步，350 个动作同时生成，约 10ms。FAST 的自回归编码是串行的：必须一个 token 一个 token 生成，等第一个生成完才能生成第二个，整个过程需要约 30～50ms。

不能并行的原因是自回归模型的本质：预测下一个 token 依赖前面所有 token 的信息，这是很难绕开的逻辑约束。不过 π 团队认为这是已知的、可以在工程上解决的问题——语言模型领域有大量现成方案（如 KV cache 等）。

| | Flow Matching（π0） | FAST（π0-FAST） |
|---|---|---|
| 序列长度 | 350 个浮点数 | 30～60 个 token |
| 时序连贯性 | 350 个值同时生成，天然保持 | 由 DCT 保证 |
| 精细任务 | 能完成 | 能完成（精度相当） |
| 训练速度 | 慢（约 10 万步） | 快 5 倍（约 2 万步） |
| 推理速度 | 快（并行，约 10ms） | 慢（串行，约 30～50ms） |

值得一提的是，系列后续会讲到把 FAST 与 Flow Matching 结合起来的工作，试图拿到两者的优点。

## 十一、总结：三个层面理解 FAST

**算法层面**：DCT 把平滑的动作曲线压缩约 10 倍，BPE 进一步学习动作中的"惯用语"。350 个浮点数被压缩成 30～60 个 token，同时时序完整性得以保留。

**工程层面**：把机器人控制完全统一到标准 LLM 训练管道中，训练速度明显提升。从此大模型领域的所有工程优化技巧，都可以很容易地应用到机器人训练当中。

**认知层面**：训练管道中一个小小的改动（tokenizer），就能带来 5 倍的效率提升——这说明 VLA 的训练远未被充分优化。数据、架构、训练目标，每一个环节都可能藏着类似量级的提升空间。
