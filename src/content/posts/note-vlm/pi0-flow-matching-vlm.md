> 本系列将按时间顺序逐篇解读 Physical Intelligence（π 团队）的技术文章。他们的目标很明确：为机器人构建一个通用基础模型，就像 GPT 之于语言。而 2024 年 10 月 31 日发布的 π0（*π0: A Vision-Language-Action Flow Model for General Robot Control*），就是一切的起点。

π0 可以理解为"视觉-语言-动作流模型"。这篇文章回答了一个根本性的问题：**怎样才能让一个机器人模型同时控制多种不同的机器人、完成各种各样的任务？**

## 一、为什么机器人 AI 做不成"通才"？

先看现状：

- 工厂里的机械臂只会焊接同一个零件，换一个零件就得重新编程；
- 仓库搬运机器人只会走固定路线，换个仓库布局就会迷路；
- 扫地机器人只能在二维地图上规划路径，让它去厨房拿杯水完全做不到。

每个任务都要工程师单独设计、单独训练一套系统。而 GPT-4 一个模型就能写代码、翻译、做数学题、聊天——不需要为每个任务单独训练。

为什么语言 AI 能做到通才，机器人 AI 却不行？差距在四个层面：

1. **数据**：语言模型的训练数据来自互联网上的海量文本，几乎免费、无穷无尽；机器人数据却要让真实机器人在真实环境里操作并录制，过程慢、成本高，而且不同机器人之间的数据还不能通用。
2. **输出形式**：语言模型输出离散 token，与 Transformer 天然契合；机器人却要输出连续信号（关节角度、速度），且每秒要输出 50 次，任何延迟都会导致动作卡顿甚至失控。
3. **错误代价**：语言说错了重新问一遍即可；机器人一个错误动作可能打翻东西、损坏设备，甚至伤人。
4. **平台**：所有语言模型共享一套词表；不同机器人的关节数量、传感器类型各不相同，没有天然统一的接口。

π0 给出的答案是：**把预训练 VLM 的语义理解能力，嫁接到机器人的控制上。**

## 二、核心思路：见多识广的大脑 + 训练有素的手

π0 的整体思路可以用一句话概括：把两件事合在一起。

1. **预训练的视觉语言模型（VLM）**：负责理解"帮我叠衣服"这句话是什么意思，看懂摄像头里的图像——衣服在哪、什么形状、该从哪里抓。这部分能力不需要从零训练，VLM 已经从互联网数据中学到了大量视觉语言知识。
2. **Flow Matching（流匹配）**：一种生成模型技术，负责把 VLM 的理解转化为实际的关节控制信号，告诉机器人每个关节的角度应该是多少，每秒输出 50 次。

打个比方：VLM 是一个见多识广的大脑，懂很多但不会动手；Flow Matching 是一双经过专门训练的、准确、快速、可控的手。π 团队做的，就是把大脑和双手连起来。

整个模型参数量 3.3B：其中 **3B 来自 VLM 骨干（PaliGemma），300M 是动作专家（Action Expert）**。

## 三、架构详解

### 3.1 输入与"双世界"设计

模型的输入有三类：

- **图像**：通常来自 2～3 个摄像头；
- **语言指令**：如"帮我把桌子上的杯子拿过来"；
- **关节状态**：机器人当前每个关节的角度。

三类输入分别经过视觉编码器、tokenizer、状态嵌入层，然后进入模型的两个核心模块。

π0 架构的关键设计理念，是把所有输入划分为**两个世界**：

- **语义世界**（VLM 骨干，3B）：处理图像 token 和语言 token。图像 token 经视觉编码器处理后，投影到与语言 token 相同的 embedding 空间——这部分和普通语言模型完全一样。
- **控制世界**（动作专家，300M）：处理关节状态和带噪声的动作块。

两个世界相互隔离，又通过 Self-Attention 互相通信：VLM 骨干告诉动作专家当前场景如何、语言指令是什么；动作专家据此决定下一步的动作方向。就像大脑和手之间的神经连接——大脑感知到杯子在那里、要往右伸，手接到信号后做出精确的动作。

注意信息流是**单向**的：从 VLM 流向动作专家。为什么？下面解释。

### 3.2 为什么不能让 VLM 直接输出动作？

最直接的想法是：VLM 这么强，直接让它输出动作行不行？答案是不行，有两个根本原因：

1. **离散 vs 连续**：VLM 输出的是离散 token，一个词一个词地输出；但关节角度是连续浮点数，不能当成词来处理。即使采用数字化的词表，精度也会大幅损失。
2. **灾难性遗忘**：VLM 在大量文本数据上预训练，权重中存储着大量语言和视觉知识。如果让它直接学习高频机器人控制信号，这种截然不同的训练信号会干扰甚至破坏原有的语言知识——这就是灾难性遗忘。

所以 π 团队设计了独立的动作专家模块：300M 参数，远小于 3B 的 VLM 骨干（降低推理开销），使用完全独立的权重。机器人控制信号的梯度不会传播到 VLM 里。消融实验也验证了：独立权重确实比共享权重性能更好。

### 3.3 三段式因果掩码

两个模块之间如何交互？π0 用了**三段式因果掩码（three-block causal attention）**。所有 token 被分成三块：

| Block | 内容 | 可见范围 |
|---|---|---|
| Block 1 | 图像 + 语言 token | 只能看自己（看不到 Block 2/3） |
| Block 2 | 关节状态 token | 可回望 Block 1，看不到 Block 3 |
| Block 3 | 动作序列 token | 可回望前面所有信息 |

每个 block 内部使用双向 attention，token 之间可以互相关注；block 之间则是单向的。

这个设计的核心目的是**防止信息泄漏**：

- 动作序列 token 可以充分利用图像、语言、关节状态的信息来生成动作——这是我们想要的；
- 反过来，图像和语言 token 看不到动作序列——这也很重要，因为一旦动作序列影响语言理解部分，VLM 预训练的语言知识就可能被污染。

单向信息流既保证了语言理解不受污染，又让动作生成能充分利用上下文。非常精妙的设计。

## 四、核心技术：Flow Matching 四步详解

Flow Matching 要解决的问题是：给定一个目标动作 $a_T$（比如关节角度应为 0.8），如何从随机噪声生成这个目标动作？分四步讲解。

### 第一步：定义一条路径

在噪声和目标之间定义一条路径，最简单的选择是**线性插值**：

$$a_t(\tau) = \tau \cdot a_T + (1-\tau) \cdot \varepsilon$$

其中 $\varepsilon$ 是采样的高斯噪声，$\tau \in [0,1]$ 表示在这条路上走了多远。

用具体数字验证：目标动作 $a_T = 0.8$，采样噪声 $\varepsilon = -0.3$：

- $\tau = 0$ 时：$0 \times 0.8 + 1 \times (-0.3) = -0.3$，纯噪声状态；
- $\tau = 0.5$ 时：$0.5 \times 0.8 + 0.5 \times (-0.3) = 0.25$，路径中间状态；
- $\tau = 1.0$ 时：$1 \times 0.8 + 0 \times (-0.3) = 0.8$，目标动作。

$\tau$ 从 0 走到 1，动作就从噪声变成了目标。

### 第二步：求速度

路径定义好了，速度怎么求？$\tau$ 就是时间步，对路径关于时间求一阶导（高中物理：位移对时间求导等于速度）：

$$v = \frac{\mathrm{d}\, a_t(\tau)}{\mathrm{d}\tau} = a_T - \varepsilon$$

这就是这条路径上的真实速度，也叫速度差。含义非常直观：**从噪声指向目标的方向向量**。

用上面的数字验证：$v = 0.8 - (-0.3) = 1.1$。

这里有个关键性质：**因为路径是直线，速度是常数**——无论 $\tau = 0.1$ 还是 $\tau = 0.9$，速度永远是 1.1，方向不变、大小也不变。这意味着沿这条路走，不需要每一步重新估计方向，只要知道速度，几步就能走完全程。**这就是 Flow Matching 比 Diffusion 快、只需要 10 步的原因**：路径是直线，不需要在中间过程矫正方向。

### 第三步：训练神经网络预测速度

训练时我们同时知道目标动作 $a_T$ 和噪声 $\varepsilon$，真实速度 $a_T - \varepsilon$ 可以直接计算。但推理时只有噪声，既不知道目标 $a_T$，也不知道真实速度。

解决方案：训练一个神经网络 $v_\theta$，学习在给定当前带噪动作和时间步的情况下预测速度。训练流程：

1. 从数据集随机采样一个真实动作 $a_T$，随机采样高斯噪声 $\varepsilon$；
2. 随机采样时间步 $\tau$，代入插值公式计算带噪动作 $a_t(\tau)$；
3. 计算真实速度 $a_T - \varepsilon$；
4. 把带噪动作、时间步 $\tau$ 和场景观测一起喂给网络，让它预测速度，用均方误差（MSE）最小化预测速度与真实速度的差距。

训练完成后，面对任意带噪状态，网络都能预测出"该朝哪里走、走多快"。

### 第四步：推理——欧拉积分

有了训练好的速度预测网络，推理就很简单了：从纯噪声出发，用欧拉积分，每一步向前走一小步：

$$a_{new} = a_{current} + h \cdot v_\theta(a_{current},\ \tau,\ o)$$

其中 $o$ 表示场景观测。步长 $h$ 设为 0.1，$\tau$ 从 0 走到 1 一共只需要 10 步。每一步都把当前带噪动作、当前 $\tau$ 和观测喂给模型，预测速度，向前走一小步。10 步之后，动作就从纯噪声收敛到了目标值。

在 4090 显卡上，Flow Matching 的 10 步去噪只需 **27ms**，即可输出 50 步动作序列，对应机器人约 1 秒的运动。

### 与 Diffusion 的对比

| | Diffusion | Flow Matching |
|---|---|---|
| 路径 | 随机游走的弯曲路径 | 直线 |
| 速度 | 每一步重新估计方向 | 常数、方向不变 |
| 推理步数 | 上百步甚至上千步 | 10 步 |
| 去噪耗时 | 100 步约 200+ms | 27ms |

对机器人来说，这个差距是决定性的：π0 单次推理总延迟约 73ms，其中 Flow Matching 的 10 步去噪占 27ms。如果换成 Diffusion 的 100 步，仅去噪就要 200 多毫秒，总延迟超过 300ms——对 50Hz 的机器人控制来说无法接受。

## 五、数据：三层来源

π0 的训练数据来自三层：

1. **互联网预训练数据**：VLM 骨干 PaliGemma 在数十亿文本-图像对上预训练，这部分 π0 直接继承，不需要从头学。
2. **开源机器人数据**：包括 Open X-Embodiment（OXE）、Bridge V2 等，占总数据的 9.1%，量不多但提供了一定的多样性。
3. **自有专有数据**（最核心）：8 个机器人平台、68 种任务、超过 1 万小时的操作演示。其中单臂数据 1.06 亿个时间步，双臂数据 7.97 亿个时间步。

数据加权方面有个技巧：每个任务在训练 Batch 里的采样概率**不**正比于样本量 $n$，而是正比于 $n^{0.43}$。这是次线性函数，增长比样本量本身慢，达到的效果是：数据量大的任务采样比例被压低，数据量小的任务不会被淹没。

8 种机器人平台包括单臂、双臂和带移动底盘的机器人，关节数量各不相同——最复杂的 14 个自由度，简单的单臂只有 6～7 个。π 团队的做法是**统一输入输出格式**，一套模型权重无缝控制所有 8 种机器人；关节数不足的维度补零，模型自己学会忽略这些无效维度。

## 六、训练策略：两阶段

π0 采用两阶段训练流程，这也成为后续 π 系列所有工作的核心范式：

- **第一阶段：预训练**。所有数据（开源数据 + 自有 68 种任务、8 种机器人）混在一起训练，让模型学到广泛的物理知识和机器人操作技术，形成通用基础能力。类比：大学阶段学数学、物理、工程基础，建立宽广的知识体系。
- **第二阶段：后训练（fine-tuning）**。只用高质量目标任务数据训练，通常 1～10 小时数据就够，目标是达到专家级精度。类比：毕业后进公司做专项培训，把通用基础能力转化为特定岗位的专业技能。

两个阶段缺一不可：从零开始后训练效果很差；只预训练不后训练精度又不够。只有两阶段结合，才能同时获得泛化性能和精度。

## 七、实验结果

**1. 开箱即用（zero-shot）技能**

模型只经过预训练、不做任何微调直接上场，对比当时最强的两个开源模型 OpenVLA 7B 和 Octo。在 5 个任务上，OpenVLA 和 Octo 在大部分困难任务上得分全是 0；而 π0 在最差的烤面包任务上达到 0.75，叠衬衫任务直接满分 1.0。评分 0～1，1.0 表示完美完成，0 表示完全失败；即使任务只完成一部分也能拿部分分。在从未见过的任务上开箱即用拿到 0.75，这个成绩在当时相当令人震惊。

**2. 语言指令跟随**

复杂多步任务（如清理桌面）中，实时给机器人提供中间步骤的语言指令（"先把杯子放到托盘上，再把餐巾扔掉，最后把餐具放好"）。三种条件对比：

- 人类专家提供中间指令：成功率 75%～85%；
- 高层 VLM 自动规划并提供指令：65%～75%；
- π0-small（没有 VLM 预训练）：只有 40%～50%。

这组实验说明两件事：VLM 预训练确实带来了语言理解能力的提升；语言指令是有效的——机器人可以通过语言被分步引导完成复杂任务。这也为后续"大模型做规划、小模型做执行"的分层架构打下了基础。

**3. 预训练的价值**

预训练 + 后训练 vs 从零训练：0.8 vs 0.2，差了整整 4 倍。预训练提供了泛化基础，让模型有能力理解任务；后训练进一步提升精度。两者缺一不可。

**4. 演示任务：叠衣服**

π 团队选择叠衣服作为整篇文章的演示任务，很有深意——它集中了机器人操作的所有难点：

- **变形物体**：衣服是软的、形状不固定，每次拿起来的形态都不一样，传统基于模型的方法完全无法处理；
- **长程任务**：完整折叠一件衣服需要 20 步以上的连续动作，每一步都要精确，任何一步失败都得从头再来；
- **自我修正**：中途被打断后，π0 会重新观察当前状态、调整策略，接着完成。

演示效果：从乱堆的衣物中取出一件，自主完成折叠和堆放，全程无人干预；移动底盘版本还能更进一步，从衣篓里取衣服、走到桌边折叠堆放。在 2024 年底之前，没有任何机器人 AI 系统能在真实场景中做到这样的完整演示。

## 八、推理管线

一次完整推理分三个阶段：

| 阶段 | 耗时 |
|---|---|
| 图像编码 | 14ms |
| VLM + 动作专家联合前向传播 | 32ms |
| Flow Matching 10 步去噪 | 27ms |
| **合计** | **73ms** |

执行策略：每次推理生成 50 步动作，对应约 0.5～0.8 秒的运动；推理完成后把前 16～25 步动作直接发给机器人执行——这叫**开环执行**：动作序列一旦发出，机器人就按预定动作逐步执行，中途不再看摄像头、不做修正。就像钢琴家演奏时不是看一个音弹一个音，而是提前把整个旋律记在脑子里，流畅地弹出来。

开环执行的好处是控制平滑、计算开销低；代价是中途出现突发状况（比如被人碰了一下）时机器人不能立刻响应，只能等下一次推理完成后再调整。控制频率 50Hz（每 20ms 发送一次关节指令），推理频率 1.2～2Hz（每 0.5～0.8 秒重新规划一次）。

## 九、总结

**π0 做了什么？** 把预训练 VLM 的语义理解，通过 Flow Matching 动作专家，转化为 50Hz 的机器人关节控制信号。

**π0 证明了什么？** 一个模型可以跨 8 种机器人平台，在叠衣服等高难度长程任务上取得实质性突破。

**π0 留下了什么？** "预训练 + 后训练"两阶段训练方式，以及"VLM 嫁接动作专家"的架构，成为 π 系列所有后续工作的设计基础。

同时作者也很诚实地列出了局限性：

1. **延迟**：73ms 对拧螺丝这类毫秒级精确控制任务仍然太慢；
2. **泛化**：训练数据主要来自固定实验室环境，换到陌生家庭场景泛化能力会下降——这个问题直到 π0.5 才真正被解决；
3. **无长期记忆**：机器人无法记住几分钟前发生的事，每次推理都是全新的——后续 π 系列推出了新的记忆架构专门解决这个问题；
4. **无自我修正**：靠数据覆盖，"见过类似情况就会处理，没见过就可能失败"。自我探索、自我改进的能力，要等到后续引入 RL 方法的工作。

在本系列的后续每一期中，我们都将看到 π0 遗留下来的每一个具体问题，如何一步步得到解决。
